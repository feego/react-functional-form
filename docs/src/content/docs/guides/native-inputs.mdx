## Native inputs

`useGetPropsForInput` builds props to spread directly on `<input>`, `<select>` and `<textarea>`:

```tsx
const getPropsForInput = useGetPropsForInput(form)

<input {...getPropsForInput('name')} />
<textarea {...getPropsForInput('message')} />
<select {...getPropsForInput('country')}>
  <option value="pt">Portugal</option>
</select>
<input {...getPropsForInput('newsletter', { type: 'checkbox' })} />
<input {...getPropsForInput('plan', { type: 'radio', value: 'free' })} />
<input {...getPropsForInput('plan', { type: 'radio', value: 'pro' })} />
```

Compared with field props, input props:

- never have an `undefined` value (`''` instead), so inputs stay controlled;
- bind `checked` for checkboxes (a boolean value) and radio buttons (the value equals `value`);
- set `aria-invalid` when the field has an error, and leave `error` out, since it isn't a DOM
  attribute. Read the error with `form.getFieldState(name).error`.

The `onChange` handler reads the value from the change event:

| Element                       | Value stored                    |
| ----------------------------- | ------------------------------- |
| text, textarea, select, radio | `event.target.value`            |
| `type="checkbox"`             | `event.target.checked`          |
| `type="file"`                 | `event.target.files`            |
| `<select multiple>`           | array of selected option values |

The `onChange` from `getPropsForField` handles events the same way, so custom components can pass
either a value or an event.

## Field state

`form.getFieldState(name)` returns everything about a field in one object:

```ts
const { value, error, invalid, touched, visited, dirty } = form.getFieldState('email')
```

## Focusing the first invalid field

Enable `shouldFocusError` and field and input props will include a `ref`. When a submission fails, the first invalid
field (in schema order, including nested forms and lists) gets focused:

```tsx
const form = useController({ schema, shouldFocusError: true })
```

Your input components need to forward the `ref` to a focusable element (React 19 passes `ref` as a prop;
on older versions use `forwardRef`). The option is off by default, so components that can't take a ref
don't get one.
